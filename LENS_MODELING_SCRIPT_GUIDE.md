# Lens-model script execution guide

This guide describes the code generated by `web_gui/lens_code_generator.py`, not
one project's fitted parameters. Read the generator and `Tian_infra.py` for the
current implementation; generated scripts under `runs/` are snapshots and are
not source files. No project FITS, masks, chains, or result plots belong in Git.

## Entry points and file ownership

1. `web_gui/app.js` collects the controls and calls the backend API.
2. `web_gui/backend_server.py` standardizes project artifacts, calls
   `generate_lens_script()` or `generate_lens_hmc_script()`, and writes the
   generated script in the active project directory.
3. `web_gui/lens_code_generator.py` owns the script text and normalized config.
   `Tian_infra.py` owns shared modeling, prior, plotting, and output helpers.
4. The local runner executes the generated script; `web_gui/sciama_gpu_runner.py`
   stages a small copy for Sciama. CPU and GPU use the same generated modeling
   script. Sciama settings and SSH credentials are local runtime configuration,
   not repository content.

For an encrypted local SSH key, the Sciama runner reads the passphrase-file
location from `HGUI_SCIAMA_PASSPHRASE_FILE`, runner config, or the user's private
`~/.config/herculensgui/sciama.json`. Never commit that local config or the key.

HMC's `custom_gibbs.py` is currently copied from the sibling
`Herculens-Extensions` checkout. Euclid download helpers are likewise supplied
by the workspace. A standalone clone needs those dependencies configured;
neither their local data nor credentials are included here.

Typical required project inputs are `Data_cutout.fits`, `PSF_model.fits`,
`mask_1.fits`, and `mask_out.fits`. `RMS_map.fits` is used when configured and
present; `mask_2.fits` is used for DSPL. Check the actual generated script's
`MODEL_CONFIG` before assuming which optional paths or stages are enabled.

## Annotated single-plane skeleton

The following is a shortened reading map, not a runnable replacement for the
generated script. Comments explain the consequential lines.

```python
# The process must run with the project folder as its working directory.
PROJECT_ROOT = Path.cwd()
import Tian_infra
Tian_infra.import_function(globals())  # Exposes JAX, NumPyro, Herculens, helpers.
jax.config.update("jax_enable_x64", True)
numpyro.enable_x64()

MODEL_CONFIG = {...}  # SVI steps/chains, priors, source grid, masks, numerics.
GUI_STATUS = Tian_infra.GUIStatus(STATUS_PATH, RUN_OUTPUT_DIR)

data, header = fits.getdata(DATA_FILE, header=True)
source_arc_mask = fits.getdata(MASK_1_FILE).astype(bool)
mask_out = fits.getdata(MASK_OUT_FILE).astype(bool)
fit_mask = ~mask_out  # Only mask_out excludes pixels from the image likelihood.
psf_kernel = fits.getdata(PSF_FILE)
psf_kernel = psf_kernel / psf_kernel.sum()  # Flux-conserving convolution.
rms_map = fits.getdata(RMS_FILE) if use_rms_map else None
# Data, RMS, mask_out, and source arc masks must have identical image shape.

pixel_grid, *_ = Geometry.get_pixel_grid(data, pix_scale)
psf = PSF(psf_type="PIXEL", kernel_point_source=psf_kernel)
noise = Noise(nx, ny, exposure_time=exposure_time)
```

`mask_1` selects image pixels for the source-grid transformation; it does not
by itself remove the remaining pixels from the likelihood. For DSPL, source 1
and source 2 have separate arc masks. Preserve the FITS array orientation and
pixel registration when preparing RMS or masks; a shape match alone is not
proof that the images align.

```python
lens_image_parametric = LensImageExtension(
    pixel_grid, psf, noise_class=noise,
    lens_mass_model_class=MassModel(["EPL", "SHEAR"]),
    lens_light_model_class=LightModel(["MULTI_GAUSSIAN_ELLIPSE"]),
    source_model_class=LightModel(["MULTI_GAUSSIAN_ELLIPSE"]),
    source_arc_mask=source_arc_mask,
    kwargs_numerics={"supersampling_factor": MODEL_CONFIG["numerics"]["supersampling_factor"]},
)

def model_lens(data_obs, source_type, k_values=None, ...):
    mass_params = Tian_infra.Mass.EPL_w_shear(...)
    lens_light = LENS_LIGHT_EXTERNAL.for_model()  # Start/fix/free per config.
    if source_type == "parametric":
        lens_image = lens_image_parametric
        source_light = Tian_infra.Light.multi_gauss_light(...)
    else:
        lens_image = lens_image_pixelated
        source_light = [PowerSpectrum.matern_power_spectrum(...)]

    model_image = lens_image.model(
        kwargs_lens=mass_params,
        kwargs_source=source_light,
        kwargs_lens_light=lens_light,
        source_add=True,
    )
    numpyro.deterministic("model_image", model_image)  # Saved for posterior plots.
    model_std = rms_map if rms_map is not None else modeled_noise(...)
    with numpyro.plate("Data masked", int(fit_mask.sum())):
        numpyro.sample(
            "obs", dist.Normal(model_image[fit_mask], model_std[fit_mask]),
            obs=data_obs[fit_mask],
        )
```

The `model_lens` function is reused across stages. It builds the same mass and
lens-light model but switches the source representation. Optional conjugate
point and point-source terms are inserted by the generator when enabled.

```python
for chain_index in range(MODEL_CONFIG["svi"]["num_chains"]):
    parametric_state = Tian_infra.SVI.run_one_chain_svi(
        model_lens, data, model_args=("parametric",), ...
    )
    # Convert the median into Herculens kwargs for previews and warm starts.
    parametric_kwargs = {...}

pixel_grid_shape = ...  # Manual or estimated from the parametric fit.
k_grid = PowerSpectrum.K_grid((pixel_grid_shape, pixel_grid_shape))
lens_image_pixelated = LensImageExtension(
    ..., source_model_class=LightModel(
        ["PIXELATED"], pixel_adaptive_grid=True,
        pixel_interpol="fast_bilinear",
        kwargs_pixelated={"num_pixels": pixel_grid_shape},
    ),
)
for chain_index, parametric_state in enumerate(parametric_states):
    pixelated_init = ResumeInit.pixelated_stage_init_from_parametric(
        parametric_state["median"]
    )
    # The source-grid/power initialization is derived from the paired chain.
    pixelated_state = Tian_infra.SVI.run_one_chain_svi(
        model_lens, data, model_args=("pixelated", k_grid.k),
        init_values=pixelated_init, ...
    )
```

An optional exact two-image solver is a later SVI stage, not a replacement for
the first two stages. An optional `semisolve(...)` then fixes the selected
chain's mass and lens light and solves a new source; disabling it must still
call `LensResultWriter.save_single_plane_svi_outputs_from_context(locals())`.
The writer saves status, chain summaries, FITS panels, and preview figures.

## HMC extension

`generate_lens_hmc_script()` appends an HMC section to a complete SVI script;
generating code does not run it. HMC initializes from pixelated SVI medians and
transforms sampled variables to unconstrained space. The current single-plane
generator builds up to three Gibbs blocks: lens light, source/point source, and
mass plus scalar RMS. It currently assigns unrecognized free variables to the
last block, so inspect `HMC_FREE_PARAMS` and `HMC_GIBBS_SITES` when adding a
parameter; do not assume the block is correct. Each block gets a NumPyro NUTS
kernel with its own acceptance target and dense-mass groups. Consult
`gibbs_sites_list` and `dense_mass` before changing priors. Each batch continues
from the last state and writes a separate NetCDF file before the concatenated
result is saved. HMC runs must use
an appropriate GPU node when submitted to Sciama.

```python
# Stack one pixelated-SVI median per chain; HMC starts from these states.
multi_svi_pixel_median = jax.tree.map(
    lambda *values: jnp.stack(values),
    *[state["median"] for state in pixelated_states],
)
free_params = hmc_get_free_parameter_list(
    model_lens, hmc_model_args, multi_svi_pixel_median
)
unconstrained_init = jax.vmap(
    lambda params: infer.util.unconstrain_fn(
        model_lens, hmc_model_args, {}, params
    )
)(selected_svi_medians)  # NumPyro NUTS expects unconstrained init_params.

gibbs_sites_list = [vars_lens_light, vars_source, vars_mass_and_rms]
# The generator filters empty groups and builds one NUTS kernel per group.
inner_kernels = [NUTS(model_lens, ...) for group in gibbs_sites_list]
outer_kernel = MultiHMCGibbs(
    inner_kernels, gibbs_sites_list=gibbs_sites_list
)
mcmc = MCMC(outer_kernel, num_chains=num_chains, ...)
mcmc.run(rng_key, *hmc_model_args, init_params=unconstrained_init)
# Subsequent batches reuse last_state/post_warmup_state and have unique files.
```

## Debugging order

1. Read `lens_model_result/status.json` and the final traceback in
   `lens_model_result/run.log`. Zero progress can indicate upload/SSH failure
   before Python started, not bad priors.
2. Validate FITS shapes, finite positive RMS, normalized finite PSF, non-empty
   masks as required, and image/RMS pixel alignment.
3. Inspect the generated project's `MODEL_CONFIG` and compare it with the GUI
   controls; do not assume an older project script reflects today's generator.
4. Check the printed `LENS_STAGE` and `LENS_CHAIN` markers to identify which
   stage actually ran. Do not launch a full SVI/HMC merely to test a path fix.
